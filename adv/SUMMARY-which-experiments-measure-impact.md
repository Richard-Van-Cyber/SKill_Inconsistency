# 哪些实验真正用来验证「运行时不一致性 → 成功率 / token / 时间」的影响

**直接回答**：只有**一个实验族**是为这件事设计的 —— **预算匹配的三臂对照**。
我这两轮做的对抗构造（adv01、adv02、01–08）是为**触发判定**设计的，**不能**用来支撑影响结论。

---

## 一、为「影响」设计的实验：matched-budget 三臂对照

| 研究 | cells | 臂 | 预算 | 说明 |
|---|---|---|---|---|
| `haiku45-threeway-20260917` | 90 | NoSkill / OriginalSkill / RepairedSkill | 60 req / 1M tok / 32K out | 10 task × 3 臂 × 3 trial |
| `directed-repair-b60-20260923` | 30 | DirectedRepairSkill | **同一预算** | 与上表可直接合并 |

**为什么只有它能回答这个问题**：

- **NoSkill vs OriginalSkill** 分离出「skill 本身（含它的不一致性）带来的影响」；
- **OriginalSkill vs RepairedSkill** 分离出「修不一致性带来的影响」；
- n=30/臂（我自己的对抗实验只有 n=3）；
- 三个维度逐 cell 记录（score / total_tokens / agent_seconds / api_calls）；
- 三臂共用同一份 runner 源码与同一模型/CLI。

### 1.1 成功率

| 口径 | NoSkill | OriginalSkill | DirectedRepairSkill | DRS − NoSkill | DRS − Original |
|---|---|---|---|---|---|
| 全部 10 task | 0.144 (n=30) | 0.271 (n=30) | **0.391** (n=30) | +0.247 | +0.119 |
| 剔除 court-form-filling（verifier 缺陷） | 0.160 (n=27) | 0.301 (n=27) | **0.323** (n=27) | +0.163 | **+0.021** |

**读数**：
- **skill 存在本身有明确影响**：0.144 → 0.271（+0.127）；
- **修不一致性对成功率几乎没有影响**：剔除 verifier 缺陷任务后只剩 **+0.021**；
  未剔除时的 +0.119 几乎全部来自 `court-form-filling`（0.000 → 1.000），
  而那是该任务 verifier 的缺陷（2 个 checkbox 测试被 **skip** 而非 fail，pytest 退出码 0 直接给 1.0）。

### 1.2 token 与时间（仅统计未被预算截断的 cell）

| 臂 | n | median api_calls | median agent_seconds | median total_tokens |
|---|---|---|---|---|
| NoSkill | 23 | 17 | 179 | 400k |
| OriginalSkill | 21 | 13 | 151 | 325k |
| DirectedRepairSkill | 23 | **16** | 165 | **529k** |

**读数**：
- **token**：DRS 比 Original 高 **+63%**，比 NoSkill 高 **+32%**。修不一致性**增加了** token 开销；
- **时间**：三臂 151–179 s，差异在噪声内；
- **调用次数**：13–17，差异小。

**结论**：在这批数据里，运行时不一致性的可测影响是
**「修它不会提高成功率，但会让 token 开销上升」**，而不是「不一致性拖低了成功率」。

### 1.3 另一个预算下的对照（不可与上表直接比）

`directed-repair-20260923`：同 10 task，但预算 **400 req / 8M tok / 200K out**（30 cells）。
它证明的是「给足预算后哪些任务能过」（mean 0.3440，19.7M tokens / $7.85），
**不能**与三臂表并列比较 —— 预算不同。

## 二、我的对抗构造：为「触发」设计，不是为「影响」

| 实验 | 设计 | 任务 | 臂 | n/臂 | 成功率 O→R | med token O→R | med agent s O→R |
|---|---|---|---|---|---|---|---|
| adv01 | 对抗数据 | adaptive-cruise-control | O / R | 3 | 0.000 → 0.000 | 1008k → 1005k | 388 → 381 |
| adv02 | 对抗数据 | offer-letter-generator | O / R | 3 | 1.000 → 1.000 | 148k → 173k | 35 → 41 |
| 03 | 对抗数据 | pddl-tpp (plan path) | O / R | 3+3 | 0.667 / 1.000 → 1.000 / 0.667 | 396/772 → 376/516 | 90/164 → 86/601 |
| 02 | 对抗数据 | grid (Type-1) | O / R | 3+3 | 0.667 / 1.000 → 1.000 / 0.333 | 210/279 → 289/293 | 91/108 → 138/122 |
| 01 | 对抗数据 | earthquake (field names) | O / R | 3+3 | 0.667 / 1.000 → 1.000 / 0.667 | 289/160 → 193/165 | 61/46 → 49/74 |
| 04 | 文档 | energy-unit-commitment | O / R | 3 | 0.000 → 0.000 | 909k → 664k | 849 → 219 |
| 07 | 文档 | lab-unit-harmonization | O / R | 3 | 0.604 → 0.465 | 517k → 344k | 124 → 99 |
| 06 | 文档 | sales-pivot-analysis | O / R | 3 | 0.333 → 1.000（混杂） | — | — |

**为什么它们不能支撑影响结论**：

1. **n=3/臂**（三臂对照是 n=30）—— 01/02/03 的 O→R 差异在 0.667 ↔ 1.000 之间来回，Fisher p=1.000；
2. **多数任务在 reward 地板**：adv01（0.000/0.000）、04（0.000/0.000）两臂都零分，
   effectiveness 根本不可测；04 号的信号只在**产出物层**（commitment = 2/3/4）；
3. **06 号归因失败**：reward 0.333 → 1.000 看似很好，但 6/6 运行从未用过被修的那个索引，
   真实自变量是文档可执行性；
4. **07 号被淹没**：机制确实触发（钳制代码 0/3 → 3/3、近边界残留 169 → 39），
   但 reward 0.604 → 0.465（p=1.000），因为主导失败是每次 1–2 万个值没做单位换算。

**它们的正确用途**：判定**某条不一致性是否被运行时触发**，以及**修复是否规避了它**
（协议里的 L1 / L2 / L3），产出物层证据。

## 三、汇总

| 问题 | 哪个实验能回答 | 答案 |
|---|---|---|
| skill（含其不一致性）是否影响成功率 | 三臂对照，NoSkill vs OriginalSkill | **是**，0.144 → 0.271 |
| **修不一致性能否提高成功率** | 三臂对照，Original vs DRS（同预算） | **几乎不能**，剔除缺陷任务后 **+0.021** |
| 修不一致性的 token 代价 | 三臂对照的 efficiency 表 | **+63% token vs Original**，时间持平 |
| 某条不一致性**是否被触发** | 我的对抗构造（01–08、adv01/02） | 8 个里 3 个在产出物层触发（02、04、07） |
| 某条不一致性**是否造成成功率下降** | **现有实验都不足以回答** | 需要：可满分任务 + n≥10 + 产出物层分类 |

**最后一行是关键缺口**：要真正把「某条不一致性」与「成功率下降」连起来，
需要的实验形态是 **同一对抗数据 × 两臂 × n≥10**，且任务本身可满分（P11）。
目前没有一条满足 —— 三臂对照的 n 够但没有对抗数据，我的对抗数据够但没有 n。
