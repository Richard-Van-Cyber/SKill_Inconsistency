# adv/ —— 对抗性任务数据实验协议

本目录按**任务**逐个记录对抗性实验。每个任务一个子目录，编号即实验顺序。

## 流程（每个任务固定四步）

```
① 构造对抗性任务数据（语义等价扰动，只改表示/取值，不改正确答案）
        ↓
② 跑 OriginalSkill × 3，验证不一致性**确实被触发**
   （判定必须落在产出物层：具体数值/文件/字段，而不是只看 reward）
        ↓
③ 依据观察到的触发点做**最小修复**（只改不一致性本身，diff 必须单变量）
        ↓
④ 跑 RepairedSkill × 3，对比触发是否消失
```

**顺序不可颠倒**：先证明触发，再据触发做修复。否则无法区分
"修复有效"与"修复恰好改到了别的东西"。

## 判定标准（三层，缺一不可）

| 层 | 证据 | 说明 |
|---|---|---|
| **L1 触发** | 产出物里出现不一致性预测的具体缺陷 | 如 commitment=3.0、超调 22%、文件是 pickle |
| **L2 归因** | 该缺陷**只能**由目标不一致性解释 | 需排除 agent 手滑、任务噪声（对照轨迹与其它 cell） |
| **L3 规避** | 修复臂在同一对抗数据上该缺陷消失 | 且 diff 只含目标不一致性（单变量） |

**只满足 reward 差异不算证据。** 已多次实测到 reward 差异来自无关噪声（01 号微秒时间戳）、
混杂变量（06 号文档可执行性）或量级淹没（07 号），而机制其实没触发。

## 每个任务目录的结构

```
adv/NN-<task>/
  README.md              本任务的完整记录（设计→触发→修复→对比）
  data/                  对抗性数据 + 与出厂数据的差异说明
  repair/<file>.original / .repaired      修复 diff 的两侧
  evidence/              机械证明输出、逐 cell 指标、分析脚本
```

## 已提炼的额外原则

**P10 · 修复只有在该不一致性是"绑定约束"时才有效。**
agent 会把文档里的代码块当**起点**改写，而不是当成品照抄。
若原臂里已有较大比例（如 2/3）的运行**自行规避**了该缺陷，说明它不是绑定约束，
修文档不会移动结果 —— 此时收益必然接近 0，应改选其它任务。

**P11 · 构造对抗数据前必须先验证任务本身可满分。**
先用参考解在**出厂数据**上跑一遍，确认 verifier 能被满足；
否则对抗数据尚未成为瓶颈，任务自带的缺陷（如 01 号的 1.95 m 车距）就已经
让某些检查不可能通过，实验无法区分两臂。

（工具：`adv/feasibility_gate.sh`。注意 `reward.txt` 的写法各任务不同，
`1` / `1.0` / `1.000` 都表示满分，**必须按数值比较**——按字符串比较会把
reward 1.000 的 `civ6-adjacency-optimizer` 误报为 FAIL。）

**P12 · 修文档要"轨迹取证"，不能只"审计取证"。**
审计报告只能说明"文档 A 与代码 B 语义不一致"；它**不能**说明这个不一致
是否真的让模型付出了代价。必须回到**原始臂的运行轨迹**里，看到它真的造成了
报错、多余的轮次或 token，才动手。判据三条同时满足才改：**E**（轨迹里有对应报错）、
**B**（该报错挡住主路径或消耗可观测代价）、**M**（能写成一两句文档陈述）。

反面教材就是本仓库的 0917 版修复：它在审计报告上做修复，给 `energy-market-pricing`
补了 `try/except cp.SCS` 兜底和一个新章节，却**从未**给出真正能一次装成功的
`pip3 install --break-system-packages`。轨迹显示它把依赖摸索从 14 条命令放大到 23 条、
token 从 287k 抬到 741k（+158%）。**没有被轨迹证据支持的修复，方向是不确定的。**

**P13 · 修复的默认方向必须是"净删除一次失败试探"。**
凡是让模型**新增一条执行路径**（新代码块、新的 try/except、新的安装/求解器尝试）
的"修复"，都不满足"不得使 token 增多、fail 增多"。安全的结构是：
把一段**已知会失败**的摸索流程，替换为**一句陈述**（如"本容器没有 X，请用 Y"）。
这样 `Δtoken < 0` 且 `Δfail ≤ 0` 是**结构性**的，不依赖模型随机性。
每一次修复都应报告文档字节增幅，并确认它远小于它消除的摸索代价
（v2 版：+0.182% 字节，vs 0917 版 +3.7%）。
