  \begin{minipage}{\linewidth}
    \footnotesize\raggedright
    \emph{Doc-only}: every file in the skill directory is documentation
    (\texttt{.md}, \texttt{.mdx}, \texttt{.markdown}, \texttt{.rst},
    \texttt{.txt}, \texttt{.org}); otherwise the skill ships artifacts, which may
    be scripts, configuration or data (26 of the 194 artifact-bearing skills
    ship no code). \emph{Find./kLine}: inconsistencies per thousand lines of the
    skill's own files, documentation and code together.\\[1pt]
    Counts and shares favour artifact-bearing skills; per line the ordering
    reverses, because doc-only skills are small (68k lines against 614k in
    GitHub) and every line of them is the kind of text a contract inconsistency
    lives in. The gap narrows but does not reverse if the denominator is
    documentation lines only (0.62 vs.\ 0.36 in GitHub, 0.20 vs.\ 0.14 in
    SkillBench). The GitHub half is the audit output \emph{without} independent
    re-verification and the SkillBench half is the post-verification survivors,
    so the two halves are not equally reliable; on the verified corpus the two
    skill kinds do not differ significantly by prevalence (61.0\% vs.\ 67.4\%,
    Fisher $p=0.65$).
